# CUDA-Benchmark-Ergebnisse vom 25./26. Juli 2026

## Messdefinition

Gemessen wird Moneros Wallet-Ableitung
`generate_key_derivation(8 * view_secret_key, tx_public_key)` für einen
konstanten geheimen Skalar und viele unterschiedliche öffentliche Punkte.
Die GPU-Zeit wird mit CUDA Events gemessen. Alle als gültig aufgeführten
Läufe endeten mit `validation=pass` und dem erwarteten Ergebnis-Checksum.

Referenz für alle Beschleunigungsfaktoren ist der Median der unveränderten
Monero-Ref10-Single-Thread-Implementierung:

```text
27,030.166 Ableitungen/s = 1.00x
```

### Launch-Bounds

C8/LB5 und C9/LB6 reduzieren die Registerzahl auf 168, erzeugen aber pro
Thread 600 Byte Stack, 756 Byte Spill-Stores und 1,320 Byte Spill-Loads.

| Messung | Ableitungen/s |
|---|---:|
| C8/LB5 kurzer Probe-Lauf | 27,320,958.865 |
| C9/LB6 kurzer Probe-Lauf | 27,274,174.126 |
| C8/LB5, 32 Threads, bester Einzellauf | **27,323,459.974** |
| C8/LB5, 64 Threads | 27,272,828.442 |
| C8/LB5, formaler Median | 26,811,990.634 |
| C8/LB5 Dauerlauf | 26,852,358.544 |
| C7 Dauerlauf zum Vergleich | **26,877,688.327** |

Der kleine Vorteil der kurzen LB5-Läufe verschwand im Dauerlauf. C7 bleibt
deshalb die robuste Endvariante.

Auf SM 12.0 begrenzen 255 Register pro Thread die theoretische Belegung auf

die Hardware-Counter des Mietsystems wegen `ERR_NVGPUCTRPERM` nicht lesen.
Die Ressourcenangaben stammen aus `nvcc -Xptxas=-v`.

## Korrektheit

- C7 und C11: erwartete Checksum und `validation=pass` in allen aufgeführten
  Sweeps, formalen Läufen und Dauerläufen.
- C11-Radix-4-Rekodierung: portable Referenzprüfung für 1,024 Eingaben mit
  Checksum `0xbcd4d9a924eb66f8`, bestanden.
- RTX 5090 C7 `compute-sanitizer --tool memcheck`: 0 Fehler.
- RTX 5090 C7 `compute-sanitizer --tool initcheck`: 0 Fehler.
- RTX 3090 C6 `memcheck` und `initcheck`: jeweils 0 Fehler.
